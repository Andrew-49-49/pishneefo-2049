# ระบบจัดการร้าน (Admin) — Pishneefo 2049

ระบบหลังบ้านสำหรับจัดการสินค้า คำสั่งซื้อ เนื้อหา และการตั้งค่าร้าน
อยู่ในโปรเจกต์เดียวกับหน้าร้าน แต่แยกโค้ดและแยก bundle ออกจากกันสิ้นเชิง

---

## เข้าใช้งานยังไง

```bash
npm install
npm run dev      # ขึ้นทั้ง API (พอร์ต 4000) และหน้าเว็บ (พอร์ต 3000)
```

แล้วเปิด **`http://localhost:3000/#admin`**

มี 2 เส้นทางที่ใช้ได้:

| URL | ต้องตั้งค่าอะไรไหม |
|---|---|
| `/#admin` | **ไม่ต้อง** — ใช้ได้ทันทีทุก host เพราะเป็น hash route |
| `/admin` | **ไม่ต้อง** เมื่อรันผ่าน `npm start` — Express มี SPA fallback ในตัว |

**ครั้งแรกที่เปิด** ระบบจะให้สร้างบัญชีผู้ดูแล ตั้งชื่อผู้ใช้และรหัสผ่านได้เลย
บัญชีนี้เก็บบนเซิร์ฟเวอร์ ใช้เข้าได้จากทุกเครื่อง

---

## สถานะปัจจุบัน

**มี backend จริงแล้ว** — Node + Express + SQLite ดูรายละเอียดที่ [`BACKEND.md`](./BACKEND.md)

- ข้อมูลอยู่ใน `data/pishneefo.db` บนเซิร์ฟเวอร์ เปิดจากเครื่องไหนก็เห็นชุดเดียวกัน
- การตรวจสอบสิทธิ์เกิดบนเซิร์ฟเวอร์ แก้โค้ดในเบราว์เซอร์ข้ามไม่ได้
- รหัสผ่าน hash ด้วย scrypt · session อยู่ใน httpOnly cookie ที่ JavaScript อ่านไม่ได้

**ยังเหลือ 2 เรื่อง:**

1. **หน้าร้านยังไม่ได้ต่อกับ API** — ยังอ่านจาก `src/data/mockData.ts` เหมือนเดิม
   แก้สินค้าใน admin แล้วหน้าร้านยังไม่เปลี่ยน (ดูหัวข้อ "ขั้นต่อไป")
2. **คำสั่งซื้อ 38 รายการเป็นข้อมูลตัวอย่าง** — กดล้างได้ที่ **ตั้งค่า → ล้างคำสั่งซื้อตัวอย่าง**
   และกดใส่กลับได้ถ้าอยากดู dashboard อีกครั้ง

## หน้าจอที่มี

### ภาพรวม (Dashboard)
- ยอดขาย 7 วัน / จำนวนออร์เดอร์ / ยอดเฉลี่ยต่อออร์เดอร์ / ออร์เดอร์ที่ค้าง พร้อม % เทียบช่วงก่อนหน้า
- กราฟยอดขายรายวัน 30 วัน (hover ดูตัวเลขรายวันได้ และกด "ดูเป็นตาราง" ถ้าอยากอ่านเป็นตัวเลข)
- สินค้าขายดี + สัดส่วนยอดจากสร้อยกำหนดเอง
- สรุปจำนวนออร์เดอร์แต่ละสถานะ
- สต็อกใกล้หมด (เกณฑ์ปรับได้ในหน้าตั้งค่า)
- คำสั่งซื้อล่าสุด กดเข้าไปดูรายละเอียดได้เลย

### สินค้า
- ตารางสินค้าทั้งหมด ค้นหาจากชื่อหรือ SKU กรองตามหมวดและสถานะสต็อก เรียงได้ 4 แบบ
- **แก้สต็อกได้ในตารางเลย** ไม่ต้องเปิดฟอร์ม — ช่องจะเปลี่ยนเป็นสีเหลืองเมื่อใกล้หมด สีแดงเมื่อหมด
- สวิตช์ "หน้าร้าน" เปิด/ปิดการแสดงสินค้าโดยไม่ต้องลบ
- ฟอร์มเพิ่ม/แก้ไข: ชื่อ, slug, ราคา, ราคาเดิม, สต็อก, หมวด, วัสดุ, SKU, รูปหลัก + แกลเลอรี, คำโปรย, รายละเอียด, ป้ายกำกับ, สินค้าแนะนำ
- ตรวจข้อมูลก่อนบันทึก (ชื่อว่างไม่ได้ ราคาต้อง > 0 ราคาเดิมต้องสูงกว่าราคาขาย)

### คำสั่งซื้อ
- ค้นหาจากเลขที่ ชื่อลูกค้า อีเมล เบอร์โทร หรือเมือง กรองตามสถานะ
- 5 สถานะ: รอชำระเงิน → ชำระแล้ว → จัดส่งแล้ว → สำเร็จ / ยกเลิก
- **หน้ารายละเอียดแสดงใบสั่งผลิตสร้อยครบ** — สีตัวเรือน จำนวนข้อ ผังว่าชาร์มตัวไหนอยู่ข้อที่เท่าไหร่ พร้อม SKU และการแยกราคาตัวเรือน/ชาร์ม
  (ตรงนี้แก้ปัญหาที่พบตอนรีวิว: หน้าร้านเดิมไม่เคยบันทึกสีสร้อยที่ลูกค้าเลือก)
- ช่องบันทึกภายในสำหรับทีมงาน
- กดพิมพ์ใบสั่งผลิตได้

### เนื้อหา
- **บทความ** — เพิ่ม/แก้/ลบ/สลับลำดับ/ตั้งเป็นฉบับร่าง
- **คำถามที่พบบ่อย** — เพิ่ม/แก้/ลบ
- **หน้า Our Story** — แก้ข้อความทั้งหมด

### ตั้งค่า
- ข้อมูลร้าน ข้อความแถบประกาศ
- ค่าจัดส่ง ยอดขั้นต่ำส่งฟรี เกณฑ์เตือนสต็อก
- อัตราแลกเปลี่ยน 4 สกุล (แสดงอัตรากลับด้านให้ด้วย เช่น 1 ฿ ≈ 732 ₫ จะได้กรอกง่าย)
- เปลี่ยนรหัสผ่าน (สร้าง salt ใหม่ และเตะทุกเซสชันอื่นออก)
- **ดาวน์โหลด / นำเข้าไฟล์สำรอง** — การนำเข้าจะไม่แตะตาราง users/sessions
- ล้างข้อมูลตัวอย่าง / ใส่กลับ / รีเซ็ตทั้งหมด

## โครงสร้างไฟล์

```

├── api.ts              ตัวเรียก REST ทั้งหมด (ไม่เคยแตะ token — อยู่ใน httpOnly cookie)
├── auth.ts             ตัวห่อบาง ๆ ของ auth API (logic จริงอยู่บนเซิร์ฟเวอร์)
├── store.ts            แคชฝั่ง client + action ที่ยิง API แล้วรีเฟรช
├── types.ts            ชนิดข้อมูลของ Order / Product / Settings
├── format.ts           แปลงสกุลเงิน วันที่ ตัวเลข
├── charts.tsx          กราฟ SVG เขียนเอง ไม่มี dependency
```

(และลบ import ที่ไม่ได้ใช้ 1 ตัวใน `HomePage.tsx` ที่ `noUnusedLocals` จับได้)

## เรื่อง accessibility

หลังบ้านทำตามที่รายงานรีวิวบอกว่าหน้าร้านยังขาด เพื่อใช้เป็นแบบอ้างอิงตอนไปแก้หน้าร้าน:

- Modal มี `role="dialog"` + `aria-modal` + ขัง focus + คืน focus ตอนปิด + Escape + คลิกพื้นหลังปิด + ล็อก scroll
- Toast อยู่ใน `role="status" aria-live="polite"` และแต่ละใบมี timer ของตัวเอง ไม่ล้างกันเอง
- ทุกช่องกรอกมี `<label>` ผูกกับ input จริง ไม่ใช้ placeholder แทน label
- ปุ่มไอคอนล้วนมี `aria-label` ทุกตัว
- ตารางมี `<caption>` + `scope="col"`
- มี skip link, `aria-current="page"` บนเมนู, `role="switch"` + `aria-checked` บนสวิตช์
- กราฟมี `role="img"` + คำอธิบาย และสลับดูเป็นตารางได้ (ไม่บังคับให้อ่านจากสีอย่างเดียว)
- สีข้อมูลในกราฟ `#2375BE` ได้ contrast 4.82:1 บนพื้นขาว · สถานะออร์เดอร์มีทั้งจุดสีและข้อความเสมอ

## ขั้นต่อไป

**ถ้าจะต่อหน้าร้านเข้ากับ API** (งานประมาณครึ่งวัน — หลังบ้านพร้อมแล้ว)

1. `src/data/mockData.ts` → ดึงจาก `GET /api/storefront` (ส่งเฉพาะสินค้าที่เปิดขายมาให้แล้ว)
2. `CurrencyContext` → อ่านอัตราจาก `settings.rates` ที่ API ส่งมา แทนค่าคงที่ในไฟล์
3. `LanguageContext` → อ่านข้อความประกาศจาก `settings.announcement`
4. หน้า checkout → `POST /api/orders` — เซิร์ฟเวอร์คิดราคาใหม่และตัดสต็อกให้เอง
   โครง `bracelet.links[].productId` รองรับสีและผังข้อสร้อยไว้แล้ว
5. ตะกร้า → เก็บลง localStorage

**สถานะ blocker จากรายงานรีวิว**

| ข้อ | สถานะ |
|---|---|
| 1.1 ตะกร้าหายเมื่อ refresh | ยังค้าง |
| 1.2 deep link 404 บน static host | **แก้แล้ว** — Express มี SPA fallback ในตัวเมื่อรัน `npm start` |
| 1.3 ช่องค้นหาหน้า Shop พิมพ์ได้ตัวเดียว | ยังค้าง |
| 1.4 Tailwind โหลดจาก CDN | **แก้แล้ว** ตอนทำ admin |
| 1.5 ปุ่ม Place order ไม่ทำอะไร | **มี API รองรับแล้ว** (`POST /api/orders`) เหลือต่อฝั่งหน้าร้าน |
| 2.1 ไม่บันทึกสีสร้อย | **แก้แล้วในโครงข้อมูล** — เหลือต่อฝั่งหน้าร้าน |
| 2.2 สั่งเกินสต็อกได้ | **แก้แล้วฝั่งเซิร์ฟเวอร์** — `POST /api/orders` ตอบ 409 |

## ขึ้น production

```bash
npm run build
npm start          # หน้าร้าน + admin + API อยู่พอร์ตเดียวกัน
```

ไม่ต้องตั้ง SPA fallback ที่ host แล้ว — Express ทำให้ในตัว
รายละเอียดการ deploy, การสำรองฐานข้อมูล และตัวแปรสภาพแวดล้อม อยู่ใน [`BACKEND.md`](./BACKEND.md)

`public/robots.txt` กัน `/admin` ไม่ให้ถูก index ไว้แล้ว
